# Mini 2 support: implementation and evidence

Research for [issue #2](https://github.com/RisinT96/pulsar/issues/2), 2026-10-31. Source references below are pinned to pulsar revision `fd434437d2aa94a1c522df7ea8ae8ed0818d7de8`. Firmware behaviour can vary between devices; the implementation describes what pulsar attempts, not proof it works on this station.

## This station: read-only observations

The task's read-only station inspection found Buildroot 2020.02.1, build ID 4793643989, compatible `yandex,station-mini2`, an armhf loader and glibc 2.30. ALSA card 0 exposed device 0 for playback and capture and device 1 for capture. The expected `libyandex_evil.so`, `libquasar_gstreamer.so`, activation models `alisa`, `yandex`, `yasmina`, command model directory, ring LEDs and clock LEDs existed. Pulsar was not installed. These are existence checks, not proof of formats, access, audio quality, clock operation or runtime compatibility; no recordings or runtime tests were made.

## Implementation and prior evidence

* **Identity and audio:** The [model profile](https://github.com/RisinT96/pulsar/blob/fd434437d2aa94a1c522df7ea8ae8ed0818d7de8/satellite/crates/pulsar-core/src/model.rs#L395-L455) selects 48 kHz, six-channel S16 `default` capture, four microphones and two speaker-reference channels, VQE preset `yandexmini_2`, and `default` playback. Its description attributes this layout to firmware ALSA configuration. The [front end](https://github.com/RisinT96/pulsar/blob/fd434437d2aa94a1c522df7ea8ae8ed0818d7de8/satellite/crates/pulsar-audio/src/frontend.rs#L1-L7) uses firmware VQE and spotter models; wake uses the gain-adjusted VQE output and level measurement uses the non-gain output. Library/model existence here does not verify the preset, capture routing, echo cancellation, recognition or HA pipeline.
* **Wake timing:** The [pre-roll rules](https://github.com/RisinT96/pulsar/blob/fd434437d2aa94a1c522df7ea8ae8ed0818d7de8/satellite/crates/pulsar-core/src/model.rs#L195-L214) use Lite 2 measurements for `alisa` and `yandex`, explicitly not measured on Mini 2. Verify wake reliability and immediate commands with and without playback; false triggers and clipped commands remain unknown. Presence of the `yasmina` directory alone does not establish its working behaviour.
* **Playback and volume:** The model uses firmware Opus earcons and `default` softvol/dmix, with a linear 0–255 Master mapping and no minimum step ([profile](https://github.com/RisinT96/pulsar/blob/fd434437d2aa94a1c522df7ea8ae8ed0818d7de8/satellite/crates/pulsar-core/src/model.rs#L385-L455)). A [host test](https://github.com/RisinT96/pulsar/blob/fd434437d2aa94a1c522df7ea8ae8ed0818d7de8/satellite/crates/pulsar-media/tests/mixer_golden.rs#L131) checks the curve, not physical loudness. HA media, TTS, earcons, Sendspin, volume and full-duplex AEC remain unverified on this device.
* **Inputs and ring:** The profile selects six RGB sysfs LEDs, `sar0_pad0`, action key 582 and GPIO 414 for latched hardware microphone mute. [Input code](https://github.com/RisinT96/pulsar/blob/fd434437d2aa94a1c522df7ea8ae8ed0818d7de8/satellite/crates/pulsar-hw/src/input.rs#L1-L10) polls the mute line every 100 ms; [opening it](https://github.com/RisinT96/pulsar/blob/fd434437d2aa94a1c522df7ea8ae8ed0818d7de8/satellite/crates/pulsar-hw/src/input.rs#L215) checks configuration rather than blindly changing GPIO direction. Sysfs presence does not validate colors, gestures, action and volume keys or mute state in either direction. GPIO numbering/configuration on this firmware remains to be checked safely.
* **Clock and sensor:** The model describes a four-digit segment panel but defaults `has_clock` and `has_lux` to false; the [controller detects actual panel and sensor at startup](https://github.com/RisinT96/pulsar/blob/fd434437d2aa94a1c522df7ea8ae8ed0818d7de8/satellite/crates/pulsar/src/controller/mod.rs#L341-L344). The earlier 0.369 device reportedly had no working clock chip, while a different 0.372 device reported working clock and a light-responsive `ltr308als01` ([upstream issue #38](https://github.com/Morvex885/pulsar/issues/38)). This station exposes clock entries; physical display, sensor presence, brightness and HA entities remain untested.

## Installation, recovery and limits of prior tests

The [installer](https://github.com/RisinT96/pulsar/blob/fd434437d2aa94a1c522df7ea8ae8ed0818d7de8/installer/probe.go#L31-L40) selects armhf for Mini 2 only when its loader exists; [tests](https://github.com/RisinT96/pulsar/blob/fd434437d2aa94a1c522df7ea8ae8ed0818d7de8/installer/probe_test.go#L24-L25) cover the selection. The installed binary targets glibc 2.23, compatible in principle with the observed 2.30; this is not an execution test. The installer checks rootfs protections before writing its init script, preserves a previous binary where available and performs a health check ([installer](https://github.com/RisinT96/pulsar/blob/fd434437d2aa94a1c522df7ea8ae8ed0818d7de8/installer/deploy.go#L259-L273), [health check](https://github.com/RisinT96/pulsar/blob/fd434437d2aa94a1c522df7ea8ae8ed0818d7de8/installer/deploy.go#L441-L511)). The [supervisor](https://github.com/RisinT96/pulsar/blob/fd434437d2aa94a1c522df7ea8ae8ed0818d7de8/satellite/deploy/supervise.sh#L1-L12) can restore `.prev` after a crash loop and return to the Yandex stack if recovery fails; a first install has no pulsar `.prev` to restore. Root access, rootfs guard outcome, storage headroom, boot persistence, rollback and dmix recovery are unknown on this station.

In [upstream PR #9](https://github.com/Morvex885/pulsar/pull/9), a contributor reported an earlier C++ build's successful install, health check and reboot on firmware 0.369 and a Sendspin/music-visualization load measurement. The maintainer subsequently ported the changes to Rust, reported host checks and Lite 2 tests, and explicitly said the Rust version had not yet been run on Mini 2, requesting a Mini 2 test including VQE, mute, playback, boot and dmix key. That prior C++ report is not evidence of a successful current Rust build on this station. [Issue #38](https://github.com/Morvex885/pulsar/issues/38) reports a working clock on another station, not a complete test of this one.

Before any live validation, follow the [station protocol](https://github.com/RisinT96/pulsar/blob/fd434437d2aa94a1c522df7ea8ae8ed0818d7de8/docs/stations.md), obtain the owner's consent for sound or volume changes, cap test volume at 0.2, and use an isolated test instance. Verify root and storage and a recovery path first; then verify the audio path, both mute transitions, keys, LEDs, clock/sensor where present, restart and recovery. Record firmware and build versions and results without publishing device identifiers, addresses, credentials or recordings.
